| **Клиент** | Директор розничного бизнеса (единый владелец по группе) | MDM‑аналитик / мастер‑данных (ведёт правила дедупликации, маппинг ID) | CRM (онбординг), внешние каналы (онлайн‑заявки) | Core, Cards, Loans, CRM, DWH, MDM | Только через MDM: создание/слияние дублей, изменение ключевых атрибутов (ФИО, паспорт). | **Счёт** | Руководитель казначейства / розничного направления | Core‑аналитик (правила статусов, типов счетов) | Core Banking (открытие счёта) | Cards, Payments, DWH, CRM (только чтение остатков) | Только Core: открытие, закрытие, смена статуса. Запрещено менять баланс вручную (только через транзакции). | Статус только из справочника; дата открытия ≤ дата закрытия; валюта из справочника; баланс всегда ≥ 0 (если не разрешены овердрафты); контроль уникальности номера счёта. |
| **Карта** | Директор карточного бизнеса | Карточный аналитик (правила статусов, PAN‑политики) | Карточная система (выпуск/активация) | Core (операции), CRM (статус), DWH (аналитика) | Только Карточная система: статусы, блокировка/разблокировка, активация. Core может запрашивать статус, но не менять его. | PAN не хранится в открытом виде (токенизация/маскирование); статусы только из справочника; запрет активации просроченных карт; контроль уникальности card_id. |
| **Кредит / Договор кредита** | Директор кредитного направления | Кредитный аналитик (скоринг, лимиты, просрочка) | Кредитная система (одобрение, выдача) | Core (погашения), CRM (обслуживание), DWH (отчётность) | Только Кредитная система: лимиты, ставки, статусы. Core фиксирует погашения, но не меняет условия договора. | Ставки из утверждённого каталога; график платежей валиден (даты возрастают, суммы корректны); статусы только из справочника; контроль просроченных дней по единому правилу. |
| **Транзакция** | Казначей / руководитель процессинга | Процессинговый аналитик (сверки, антифрод) | Core / Процессинг (проведение операции) | DWH, Data Lakehouse, антифрод‑системы | Только Core/Процессинг: проведение, отмена, сторно. Запрещено редактировать суммы/даты после проведения. | Идемпотентность (защита от дублей); контрольные суммы; timestamp в UTC; статус только из справочника; обязательная привязка к счёту. |
| **Продукт / Тариф** | Продуктовый директор | Продуктовый аналитик (версионирование, каталоги) | Каталог продуктов (через workflow) | Core, Cards, Loans, CRM, DWH | Только через workflow: создание/обновление/деактивация. Изменения вступают в силу с даты valid_from. | Уникальность product_id; даты не пересекаются (один активный тариф на период); правила валидации тарифов (минимальные/максимальные ставки); запрет удаления активных продуктов. |
| **Обращение клиента (Case)** | Руководитель контакт‑центра | CRM‑аналитик (SLA, статусы, категории) | CRM / Контакт‑центр (регистрация обращения) | CRM, DWH (метрики SLA), Core (привязка к договору) | Только CRM: статусы, назначение, резолюции. Core может добавлять комментарии, но не менять статус. | Статусы только из справочника; обязательное заполнение канала/категории; контроль SLA (время до назначения/ответа); запрет пропуска обязательных этапов workflow. |
| **Договор (юридический)** | Юридический директор | Архивист / юридический аналитик (версии, подписи) | Core / Электронный архив (подписание, загрузка сканов) | Core (метаданные), S3 (файлы), DWH (агрегации) | Только через подписанный процесс: создание версии, подпись, публикация. Запрещено удалять или изменять опубликованные версии. | Цифровая подпись версии; неизменяемость файлов (S3 object lock); контроль версий (v1, v2…); обязательная привязка к клиенту/счёту. |
| **Платёж** | Казначей | Платёжный аналитик (маршрутизация, лимиты) | Платёжная система / шлюз (создание поручения) | Core (результат), DWH (сводная отчётность) | Только Платёжная система: создание, отмена, изменение до отправки. После отправки—только статусы через интеграцию. | Валидация реквизитов; лимиты на сумму/количество; контроль дубликатов (payment_id); обязательные поля (сумма, валюта, получатель). |
