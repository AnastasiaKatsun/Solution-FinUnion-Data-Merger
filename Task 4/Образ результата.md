## Образ целевого результата (To‑Be через 12 месяцев)

| Вопрос | Что описать |
| --- | --- |
| **Какие системы остаются** | **Core Banking (RB и FU)**—как мастер‑системы по счетам/транзакциям; **CRM (RB и FU)**—для клиентских операций; **MDM**—единый источник истины по клиентам и справочникам; **Kafka**—событийная шина; **DWH на PostgreSQL**—витрины для BI и регуляторики; **Data Lakehouse (S3/MinIO + Delta/Iceberg)**—сырые и исторические данные; **Airflow + dbt**—оркестрация и трансформации; **DataHub**—каталог, lineage, владельцы; **BI**—дашборды. |
| **Какие выводятся из эксплуатации** | **Старые выгрузки в Excel/CSV «вручную»** (ручные отчёты, самописные скрипты); **локальные витрины в файлах и неподдерживаемых базах** (Access, старые MySQL‑песочницы команд); **прямые запросы из Core в BI** (обход DWH); **самописные коннекторы без mTLS** (небезопасные интеграции). |
| **Какие данные мигрируются** | **Клиентские профили** из разрозненных CRM в MDM (с дедупликацией и маппингом на global_client_id); **истории транзакций** из архивов Core в Lakehouse (в неизменяемом виде); **справочники статусов и продуктов** в единые витрины DWH; **остатки и текущие статусы счетов** в витрины DWH для BI и UI (Naive UI). |
| **Какие потоки переключаются** | **Потоки транзакций**: с прямых выгрузок/ручных файлов → на CDC (Debezium) → Kafka → DWH/Lakehouse; **клиентские данные**: с разрозненных источников → в MDM → далее во все системы по global_client_id; **отчётные выгрузки**: с ручных скриптов → на пайплайны Airflow → подписанные/зашифрованные файлы для регулятора; **события каналов** (чат, мобильное приложение): в Kafka → Lakehouse → агрегаты в DWH. |
| **Критерии завершения перехода** | **100% транзакций** загружаются через CDC/Kafka (без ручных файлов); **все системы используют global_client_id** из MDM; **SLA витрин BI ≤ 1 ч**, статусов ≤ 15 мин; **наличие lineage в DataHub** для всех ключевых витрин; **mTLS включён на всех интеграционных потоках**; **проведены тесты фолбэка** (переключение на резерв, восстановление из бэкапа); **документация по data‑продуктам** (владелец, SLA, контракт) зафиксирована в DataHub. |
