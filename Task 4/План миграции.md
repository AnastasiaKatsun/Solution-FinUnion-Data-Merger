## Этап 1. Data Discovery & Inventory (Инвентаризация)

| Поле | Содержание | Результат |
| --- | --- | --- |
| **Этап** | Data Discovery & Inventory |  |
| **Содержание** | Инвентаризация всех систем (Core, CRM, старые витрины), таблиц и потоков данных; выявление владельцев данных; фиксация SLA и частоты выгрузок; выявление ручных процессов (Excel, скрипты); определение чувствительных данных (PII) для маскирования. | Реестр систем и потоков; список ручных выгрузок; перечень PII‑полей; список владельцев по доменам (Cards, Loans, Core, CRM). |

| --- | --- | --- |
| **Этап** | Foundation & Security |  |

## Этап 3. Core CDC & First Fact (CDC из Core и первая фактовая витрина)

| Поле | Содержание | Результат |
| --- | --- | --- |
| **Этап** | Core CDC & First Fact |  |
| **Содержание** | Настройка Debezium для Core Banking (RB/FU) и публикация транзакций/счетов в Kafka; загрузка в Lakehouse (сырые события); построение первой витрины fact_transactions в DWH; запуск базовых тестов качества (dbt): уникальность, диапазоны, контрольные суммы. | Потоки CDC → Kafka → DWH/Lakehouse; первая стабильная витрина для BI; тесты качества работают; SLA витрин ≤ 15–60 минут. |

| Поле | Содержание | Результат |
| --- | --- | --- |
| **Этап** | MDM & Customer 360 |  |

## Этап 7. Cutover & Stabilization (Cutover и стабилизация)

Этот этап—финальный, но он опирается на результаты всех предыдущих.

| Поле | Содержание | Результат |
| --- | --- | --- |
| **Этап** | Cutover & Stabilization |  |
| **Содержание** | Тестовый cutover (T‑7): параллельная работа, сверка отчётов; финальные бэкапы и проверка фолбэка (T‑1); переключение потоков в день Cutover; контроль расхождений (T+1, T+7); фиксация владельцев и SLA в DataHub; обновление документации. | Старые потоки отключены; все витрины из DWH; lineage в DataHub; подтверждённые SLA; готовые документы (cutover‑план, матрица рисков, ТЗ). |
